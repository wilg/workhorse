# Commit (Cursor)

Read and follow the workflow defined in `COMMIT.md` in the same directory as this file.

## Cursor specifics

- Use Cursor's **clarifying questions** to resolve commit scope when ambiguous — which logical change, include/exclude borderline files, staging vs drafting vs full commit.
- If the work involved broad agent edits, review the diff or restore from a **checkpoint** before committing so you only capture the intended logical change.
- Run git commands via the **Terminal** tool. Use the built-in linter auto-fix to catch issues before committing.
